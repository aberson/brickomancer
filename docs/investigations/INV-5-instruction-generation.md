# INV-5: Instruction Generation Pipeline

**Question:** Given a complete LEGO brick placement (which brick goes where in 3D space, with colors), how do we generate a step-by-step instruction booklet similar to official LEGO instructions?

---

## Executive Summary

**Recommended pipeline:** Python emits a `.ldr` (LDraw) file → LPub3D headless CLI (`lpub3d -pdf -o <dir> <file>`) → publication-quality PDF.

LDraw is a trivially simple plain-text format; no library is needed to write it. LPub3D is the only maintained open-source tool with confirmed headless PDF export. The pipeline from brick placement data to a polished instruction book is a `subprocess.run()` call away.

---

## 1. LDraw File Format (.ldr / .mpd)

LDraw is plain text, line-oriented. Every non-blank line starts with a line type integer (0–5):

| Type | Purpose |
|---|---|
| 0 | Comment or META command |
| 1 | Sub-file reference (brick placement or submodel) |
| 2 | Line (edge) |
| 3 | Triangle |
| 4 | Quad |
| 5 | Optional/conditional line |

**Brick placement — Type 1 syntax:**
```
1 <color> <x> <y> <z>  <a> <b> <c>  <d> <e> <f>  <g> <h> <i>  <filename.dat>
```
- `<color>`: LDraw color code (e.g. 1=blue, 4=red, 14=yellow, 15=white)
- `<x> <y> <z>`: position in LDraw Units (LDU). 1 stud width = 20 LDU; 1 brick height = 24 LDU
- `<a>...<i>`: 3×3 rotation matrix. Identity = `1 0 0 0 1 0 0 0 1`
- `<filename.dat>`: part number from library (e.g. `3001.dat` = 2×4 brick)
- Coordinate system: right-handed, **-Y is "up"** (Y increases downward)

**Minimal valid 3-step .ldr file:**
```
0 Example Model
0 !LEOCAD MODEL DESCRIPTION My Model

1 4 0 0 0 1 0 0 0 1 0 0 0 1 3001.dat
0 STEP

1 1 20 0 0 1 0 0 0 1 0 0 0 1 3001.dat
0 STEP

1 14 0 -24 0 1 0 0 0 1 0 0 0 1 3001.dat
0 STEP
```

**Key META commands for instructions:**
- `0 STEP` — marks the end of one build step. Everything between two STEP lines is "added in this step."
- `0 ROTSTEP <rx> <ry> <rz> <ABS|REL|ADD>` — rotates the view for the next step

**MPD (Multi-Part Document):** Wraps multiple `.ldr` files in one container for subassemblies. First FILE block is the root.

**LDraw is trivially simple to emit in Python** — no library strictly needed for V1:
```python
def write_ldr(bricks, steps, title="Brickomancer model"):
    lines = [f"0 {title}\n", "0 !LEOCAD MODEL DESCRIPTION Generated by Brickomancer\n"]
    current_step = 0
    for brick in sorted(bricks, key=lambda b: b.y):
        if brick.y > current_step:
            lines.append("0 STEP\n")
            current_step = brick.y
        x = brick.x * 20 + (brick.width - 1) * 10
        y = -(brick.y * 24)
        z = brick.z * 20 + (brick.length - 1) * 10
        lines.append(f"1 {brick.color_id} {x} {y} {z} 1 0 0 0 1 0 0 0 1 {brick.part_id}.dat\n")
    lines.append("0 STEP\n")
    return "".join(lines)
```

**Coordinate system summary:**

| LEGO unit | LDU | mm |
|---|---|---|
| 1 stud pitch (XZ) | 20 LDU | 8 mm |
| 1 brick height (Y) | 24 LDU | 9.6 mm |
| 1 plate height (Y) | 8 LDU | 3.2 mm |

## 2. LPub3D — Headless CLI PDF Generation

**What it is:** LPub3D (by Trevor Sandy) is the dominant open-source LEGO instruction authoring tool. Qt-based GUI app that reads LDraw/MPD files and renders multi-page instruction PDFs with callouts, parts lists, bill-of-materials, and step count badges.

**Headless/batch mode confirmed:**
```bash
lpub3d -pdf -o <output_dir> <model.ldr>
lpub3d -png -range 1-10 -o <output_dir> <model.ldr>
lpub3d -jpg -o <output_dir> <model.ldr>
```
- `-pdf`: export full instruction document as PDF
- `-png` / `-jpg` / `-bmp`: export each page as an image
- `-range <pages>`: restrict to a page range
- `-o <path>`: output directory
- `-?` or `--help`: full flag listing at runtime

**Output quality:** Publication-quality — anti-aliased rendering, proper callout boxes, step numbering, parts-added-this-step sub-lists (PLI), matches official LEGO instruction style.

**Caveats:** CLI documentation is sparse (designed as a GUI app first). Exact flags best confirmed via `lpub3d -?` at runtime. Windows headless operation works but has had bugs in some versions before v2.4.4.5. **Docker/AppImage is the most reliable headless path on Linux.** For Windows: test early in Step 9 of the build plan.

**Output formats:** PDF, PNG, JPG, BMP (instruction pages), HTML/CSV/BrickLink XML (parts lists), POV/OBJ/STL/DAE (3D export).

**License:** GPL v3. Acceptable for personal local use. Review subprocess-isolation exemption before any public deployment.

## 3. LDView — Headless PNG Rendering

**What it is:** LDView (by Travis Cobbs) is the standard LDraw renderer. Used internally by LPub3D. Can also be used standalone for batch PNG rendering.

**Key CLI flags:**
```bash
LDView model.ldr -SaveSnapshot=output.png
LDView model.ldr -SaveSnapshot=output.png -SaveWidth=1920 -SaveHeight=1080
LDView model.ldr -SaveZoomToFit=1 -AutoCrop=1 -SaveAlpha=1
LDView model.ldr -cg45,30,800             # camera: 45° lat, 30° lon, distance 800
```

**Rendering per step:** LDView does NOT auto-render each `0 STEP` as a separate image by itself. Workaround: emit one partial `.ldr` per step (containing only bricks up to that step) and render each. LPub3D handles this automatically.

**Output formats:** PNG (with alpha), BMP, JPG. Also exports POV, STL, 3DS via `-ExportFile`.

**Brickomancer use:** Call LDView headless to render suggestion preview PNGs (one per suggestion). LPub3D handles the per-step rendering internally for the instruction book.

## 4. Other Tools (Not Viable for Automation)

- **BrickSmith** (macOS): GUI-only, no headless support.
- **MLCad** (Windows): GUI only, aging (last updated ~2010s), superseded by BrickLink Studio.
- **LeoCAD:** Has experimental CLI for rendering images. Primarily GUI; cannot generate instruction-book layout. Useful as a viewer only.
- **LIC (LEGO Instruction Creator):** Python + OpenGL desktop app. Unmaintained as of ~2018. No headless/CLI mode.

## 5. Python LDraw Libraries

### pyldraw (michaelgale/pyldraw) — RECOMMENDED
- PyPI: `pip install pyldraw`
- **Status:** Actively developed, explicit replacement for ldraw-py (being archived). Python 3.9+, compatible with 3.12.
- **Capabilities:** Create, modify, read LDraw files. Color handling via `LdrColour`.
- **Verdict:** Best choice if a library is needed. Public API docs are thin — read source.

### python-ldraw (rienafairefr)
- PyPI: `pip install python-ldraw`
- **Status:** Dormant upstream (last upstream commit 2011); fork has some CI activity.
- **Capabilities:** Full brick placement API with `Piece`, `Vector`, `Identity`, `Parts` classes. Bundled parts library. Conversion tools: ldr2pov, ldr2png, ldr2svg.
- **Verdict:** Functional for basic use, but stale. Old Python compat (2.7, 3.4+).

### Write LDraw directly (no library) — V1 APPROACH
For Brickomancer's use case, writing `.ldr` files directly from Python using string formatting is entirely viable and avoids library dependency risk. The format is well-specified and trivial to emit.

## 6. Step Sequencing Algorithm

Official LEGO instructions are hand-authored. For automatic generation:

### Layer-based (bottom-up Y sorting) — simplest, V1 approach
```python
def auto_steps(bricks, bricks_per_step=8):
    sorted_bricks = sorted(bricks, key=lambda b: (b.y, b.x**2 + b.z**2))
    return [sorted_bricks[i:i+bricks_per_step]
            for i in range(0, len(sorted_bricks), bricks_per_step)]
```
- Sort by Y ascending (ground up), sub-sort by distance from center (inner-to-outer)
- Group into batches of N bricks per step (default: 8)
- Limitation: doesn't respect connectivity or structural support ordering

### Deconstruction simulation (V2 approach)
1. Start with complete model
2. At each iteration, find bricks that can be removed without disconnecting the rest ("boundary" bricks)
3. Reverse the removal sequence to get the build order
4. Group N boundary bricks per step

This is physically correct — respects that overhanging bricks must be placed after the bricks they rest on.

## 7. Alternative: Custom PDF Without LPub3D

If LPub3D is unavailable, a custom Python PDF pipeline is viable:

1. Emit per-step partial `.ldr` files (one per step)
2. Render each to PNG using LDView CLI
3. Assemble PNGs into PDF using ReportLab

**What this requires:**
- LDView installed and on PATH
- Per-step `.ldr` file generation (simple Python loop)
- Parts list extraction from brick list per step
- Layout design (step number badge, arrow overlays are custom work)

**Output quality:** Can match official LEGO instruction aesthetics with effort. Missing vs. LPub3D: automatic callout rendering, LGEO photo-realistic parts, PLI icons, automatic page fitting.

**Verdict:** Implement as a fallback only if LPub3D headless proves unreliable on Windows.

## Recommended Pipeline for Brickomancer V1

```
brick_builder data (BrickPlacement list with step, color, position)
        │
        ▼
Python: emit .ldr file (plain string formatting)
  - Sort bricks by Y, group into 8-per-step batches
  - Insert 0 STEP markers
        │
        ▼
LPub3D headless: lpub3d -pdf -o tmp/<uuid>/ suggestion_N.ldr
  - Produces publication-quality PDF
  - Auto-generates PLI, page numbers, step badges
        │
        ▼
tmp/<uuid>/suggestion_N.pdf  ← instruction booklet
```

**For preview PNGs (one per suggestion, shown in the gallery):**
```bash
LDView suggestion_N.ldr -SaveSnapshot=suggestion_N_preview.png \
  -SaveWidth=800 -SaveHeight=600 -SaveZoomToFit=1 -AutoCrop=1 -SaveAlpha=1
```
